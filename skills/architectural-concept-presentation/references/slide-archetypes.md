# 页面原型库

从信息关系选择构图，不按页码轮流套模板。允许组合与自定义。括号是可选 JSON 标识。

| 原型 | 页面任务与构图 | 设计重点 |
| --- | --- | --- |
| 1. 主视觉封面（minimal-cover） | 强图或强排字＋项目名 | 主体和标题有张力，少堆信息 |
| 2. 议程导航（contents-matrix） | 少量章节＋清晰次序 | 按需使用，不列每页 |
| 3. 章节转场（chapter-divider） | 主题、大数字或图片条带 | 长稿呼吸，短稿可省 |
| 4. 核心主张（narrative-hinge） | 一个问题/观点＋留白 | 后面立即以视觉回答 |
| 5. 问题与机会（problem-opportunity） | 真实情境图＋局部标注 | 看见切入点，少背景段落 |
| 6. 概念来源（concept-equation） | 来源元素 → 规则 → 结果 | 来源必须真正改变设计 |
| 7. 设计推导（generation-sequence） | 3–5 个一致视角阶段 | 每步一个动作，因果清楚 |
| 8. 系统关系（system-diagram） | 主体、组件与关系 | 不把段落放进框里充数 |
| 9. 单层分析（analysis-map） | 底图/界面/对象＋分析层 | 只突出本页问题 |
| 10. 整体方案（solution-overview） | 主图统领＋2–4 处标注 | 先建立整体理解 |
| 11. 构成与爆炸（exploded-view） | 零件、层级、模块分离 | 对应关系正确，标签靠近 |
| 12. 局部细节（detail-spotlight） | 主体＋重点细节放大 | 解释细节价值 |
| 13. 路径与旅程（journey-flow） | 触点或节点串联 | 顺序可读，不虚构时间/流量 |
| 14. 场景演示（scenario-demo） | 体验图或分镜＋短文案 | 展示使用与感受 |
| 15. 方案主图（rendering-hero） | 产品/空间/界面大图＋标题 | 吸引力、少文字 |
| 16. 材质与视觉语言（moodboard） | 主图＋材质、颜色与元素 | 有取舍、有设计选择 |
| 17. 方案对比（scheme-comparison） | 同条件 2–3 案＋标准 | 公平比较，有依据取舍 |
| 18. 价值与下一步（value-close） | 核心回顾＋一个决定 | 记住方案，知道下一步 |

数据明确可用 data-chart；密集证据用 technical-table 放附录；特殊表达用 custom 并说明构图。

空间类项目仍可选旧标识 context-map-split、brief-program-map、masterplan-hero、stacked-axon-program、plan-section-plate、plan-plus-locator、plan-plus-rendering；它们不是通用必备页。image-evidence-collage、dark-concept-field、closing 也兼容。

## 组合示例

- 品牌：主视觉 → 定位机会 → 概念提取 → 视觉语言 → 应用样机 → 选择。
- 产品：困扰 → 整体方案 → 构成细节 → 操作分镜 → 场景主图 → 验证计划。
- 空间：体验预览 → 切入点 → 推导 → 整体关系 → 路径 → 重点体验。
- 服务：旅程问题 → 流程回应 → 触点 → 界面演示 → 价值与待验证项。

原型不能替代具体设计；每套提案都应有项目自己的视觉内容。
