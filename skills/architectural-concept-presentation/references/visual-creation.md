# 图解与演示图创作

视觉是方案内容的一部分。缺图时先判断要表达什么，再主动设计图解或演示，不退回长段文字。执行创作须在内容确认之后。

## 按信息选择媒介

| 信息 | 优先形式 | 关键要求 |
| --- | --- | --- |
| 结构、组成、层级 | 构成、爆炸、关系图 | 构件有设计含义；非真实比例时说明示意 |
| 推导、变化 | 3–5 步序列、前后对照 | 同视角与尺度，每步一个主要变化 |
| 体验、旅程 | 分镜、场景演示、界面 | 主体一致，触点有先后，提案功能不冒充已实现 |
| 材质、情绪、视觉语言 | 拼贴、材质板、色彩提取 | 主图统领，辅助图解释设计选择 |
| 空间、位置 | 基于源图的定位、路线、分区 | 底图真实，单层信息，标识可读 |
| 定量比较 | 原生数据图表 | 数据、单位、坐标与来源核对，禁止拿生成图作数据依据 |
| 整体吸引力 | 效果图、产品/场景主视觉 | 一个主体、可信细节、留给文字的安静区域 |
| 设计取舍 | 同条件对比、局部放大 | 不用渲染质量或裁切差异操纵选择 |

关系用可编辑矢量，复杂场景/材质用图像工具。不要让图像模型生成必须精确的中文、数字、标志或连线拓扑。

## 图解制作

1. 写一句本图要解释的关系与设计动作。
2. 列出元素、连接、顺序、分类和依据；没有数据就用定性示意，不用面积/大小暗示数量。
3. 定义主次，区分主路径、辅助线与背景；最大是视觉重点，不暗示未证实数量。
4. 使用统一线宽、箭头、角度、圆角和语义颜色，标注靠近对象。
5. 放回页面，检查不读长文能否理解；否则简化或拆页。

矢量同样需要设计：间距精确、焦点清楚、连线避让。不要用随机彩色圆圈、图标或文本框充数。

## AI 场景 / 演示图创作说明

每次调用前写具体 brief：用于哪页、展示什么价值；依据哪些源图与原型；必须保持的特征；主体、构图、视角、背景、材质、光线与风格；宽高比与留白；哪些是新提案、哪些不能改变；禁止生成的正文、精确标签、标志或无依据数据。

示例：基于用户展台原型，生成访客操作核心装置的概念场景；保持装置轮廓、入口和三处交互点；人眼高度、暖白光、中性灰，蓝色仅标交互区；左侧留白用于后叠中文标题。不得新增显示屏或已落地标志。原型未给出的材质作为提案记录。

先做一个有目的的版本，根据具体问题修改，不盲目批量出十几张。支持参考图编辑时优先用参考保持一致，多图共用特征清单和风格约定。

## 检查与修正

检查构件数量、主体形态、空间/产品关系、材质、光影、人物比例、跨图一致性、错误文字与虚构标志。对卖点有决定作用的关系必须与资料核对，漂亮不等于正确。

结果不稳定时改用源图＋矢量标注、简化示意、局部裁切或更可控绘制。不能用相似外观掩盖设计差异。

保留原图、来源、brief 与关键修改记录。可能误读时页面短标“概念演示”“设计建议”；内部工具名与生成日志保存在源文件/备注。

## 缺少工具

原生形状、SVG、矢量拼贴或用户素材可完成的部分继续完成。复杂渲染无法实现时提供创作 brief，说明缺少的能力；不以大段文字或空框冒充成图。让用户选择补图或接受清晰的概念示意。
