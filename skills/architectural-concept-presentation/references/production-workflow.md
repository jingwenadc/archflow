# 制作工作流

## 找到值得讲的设计

读项目资料与参考，提取受众、问题、硬约束、核心设计、差异和已有依据。区分事实、现有设计、参考风格与拟创作内容，不能移植参考项目事实。

建立内部素材索引：编号、文件/页码、内容、清晰度、使用限制。依据页面任务选择，不按上传顺序平均分配，不把所有资料搬上屏幕。

提出一条有依据或明确属于提案的主张，例如“用一条连续参观路线串联三个体验阶段”。回答：观众为什么关心？设计做了什么？什么图能展示它？哪些效果尚未验证？

## 第一步：只交付议程

按受众决策设计章节顺序。可以先给出最有吸引力的方案预览，再解释由来；不要求从背景分析讲起。

纯文字列出主张、章节、篇幅与每章任务。页数跟着内容和素材走，不默认 28 页，不加入无关技术章节。只问会改变方向的问题。提交并等待确认，遵循 approval-gates.md。

## 第二步：只交付逐页内容

把已确认议程展开为 Markdown：实际标题、精简上屏文字、主视觉与标签、资料依据、缺图时如何创作。完整新稿覆盖全稿；局部任务覆盖约定范围。

规划三条线：
- 叙事：吸引兴趣 → 问题/机会 → 设计回应 → 体验/差异 → 选择；随项目调整。
- 画面：大图、关系图、推导、对比或细节；避免连续同一种构图。
- 真实程度：来源事实、设计提案、待验证假设分别是什么。

在文字阶段删掉空泛卖点和冗余页。提交并等待确认；此时仍不生成图像、页面或排版代码。

需要自动校验时可将相同内容映射为 storyboard-example.json 的字段，运行 check_storyboard.py。不要让用户重复审阅两份格式。

## 第三步：视觉创作与页面制作

确认范围和工具，读 visual-system.md、visual-creation.md、slide-archetypes.md 与案例图谱。用几句说明艺术方向：视觉情绪、字体、主色、图像处理、网格与图解语言。

1. 在授权范围内用一张主视觉页、一张图解页校准风格；单页任务就做好该页。
2. 先确定主视觉如何讲清卖点，再制作图片/矢量与标签。图文同步精简，不把长草稿直接排入。
3. 图解优先用原生形状、矢量、可编辑连线；场景/渲染/材质使用可用图像工具。AI 图必须给出明确构图与项目约束，检查后置入。
4. 用少量组件保持一致，允许满版大图、非对称分栏、跨栏、细节放大等变化。
5. 检查最终文案、字号、颜色含义、图像比例和内容状态；来源放备注，必要概念标识放页面。
6. 按章节或小批次制作，先检查再扩展，避免错误复制到全稿。范围小就一次完成，范围大分批交付。
7. 保存各审阅版本与真实下载入口。用户未要求时不批量尝试大量视觉变体。

## 第四步：看图验收与整合

逐页看实际渲染，检查裁切、字体、对齐、清晰度、焦点和事实一致性；看缩略图总览，检查重复、单调与节奏。对照参考评估图像与图解质量，不只检查文件能打开。

按 quality-gates.md 返工具体不合格页面。使用选定版本整合，统一风格，重新检查整合稿。交付 PPTX、可用预览、源文件和简短版本说明。渲染或导出能力不足时如实说明未验证项，不声称完整视觉验收。
