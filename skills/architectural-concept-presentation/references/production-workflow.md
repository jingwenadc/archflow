# 制作工作流

ArchFlow 网站运行时，以服务器的已批准提纲、完整策划、授权批次、检查点和版本记录为准；网站的批次预览与审校工具替代本地 `project-state.json`/脚本/目录步骤。以下文件命令和章节路径只适用于独立文件制作。两种模式都不得跳过提纲和完整策划的明确批准。

本流程受 [人工审批门禁](approval-gates.md) 约束。整体骨架未批准时不得编写逐页故事板；完整逐页故事板未批准时不得生成任何幻灯片。故事板批准后采用范围授权，可跳转或并行处理不同章节。

## 1. 资料清点与证据映射

做提纲前先清点所有资料：

| 类别 | 常见文件 | 应提取 | 不得推断 |
| --- | --- | --- | --- |
| 任务书 | DOCX、PDF、邮件 | 场地、功能、受众、范围、限制、日期 | 未写明的批准状态或优先级 |
| 基础图纸 | CAD 导出、PDF、图片 | 边界、楼层、轴网、房间名、流线 | 缺失尺寸或合规几何 |
| 场地证据 | 地图、测绘、现场照片 | 出入口、邻接、地形、已知气候条件 | 法定边界或测绘精度 |
| 设计证据 | 草图、体块、平面、剖面、模型 | 拟议空间动作和关系 | 可建造性或工程审核结论 |
| 视觉素材 | 效果图、照片、情绪板 | 氛围、材质、视点、预期用途 | 建成状态或甲方批准 |
| 品牌资料 | 标志、字体、色彩规范 | 准确的品牌资产 | 替代标志或非官方颜色 |

建立内部素材清单，为每项素材设置稳定编号，并记录来源路径、页码或图号、类型、宽高比、目标页面、裁切规则和是否允许复用。总平面或定位图只有在承担跨页定位作用时才可重复；其他主视觉原则上不重复。

## 2. 提交整体骨架并停止

资料足以开始时应完成分析并提交整体骨架。只有缺失答案会改变骨架时才提问，例如受众、截止时间、语言、指定页数、交付模式或当前有效方案。

整体骨架必须写明章节顺序、每章的叙事任务、预计页数、已有资料、缺失资料和关键假设。提交后停止，不得生成逐页内容或幻灯片，直到用户明确批准整体骨架。

## 3. 骨架批准后确定叙事深度

- **10–18 页，会议汇报**：聚焦决策，只保留最强证据和比较。
- **20–36 页，甲方概念方案**：默认模式，包含完整逻辑和精选图纸、效果图。
- **40–80 页，设计方案文本**：展开分析、楼层或分区序列和必要技术附录。
- **80–120 页，竞赛或评审文本**：仅在资料足够时使用，必须依靠章节节奏和附录，不能为凑页数注水。

页数包含封面。用户指定页数时以用户要求为准。

## 4. 建立论证

先在内部各写一句：

- 项目条件：哪些内容已经确定或可以观察？
- 设计问题：条件引出了什么冲突或机会？
- 设计命题：用什么核心回应组织方案？
- 设计动作：命题如何影响规划、体量、流线、立面、景观或室内？
- 证明材料：哪张平面、图解、剖面、效果图或数据证明每个动作？

没有证明的动作，应补充所需视觉、明确写成开放提案，或删除。

## 5. 提交完整逐页故事板并停止

每个故事板条目必须包含 id、chapter、title、purpose、takeaway、slide_copy（拟展示给观众的短文案）、visual_plan（具体图表/画面及其作用）、archetype、evidence 和 assets。可选字段包括 status、notes 和 reuse_reason。策划文案可在正式排版时校订，不得把 purpose 或 visual_plan 当作最终页面正文。使用检查器：

    python scripts/check_storyboard.py storyboard.json

良好顺序交替使用四类页面功能：

1. **定位**：位置、任务书、场地、功能。
2. **推导**：诊断、设计标准、机会。
3. **回应**：概念、生成、分区、流线。
4. **证明**：总图、平面、剖面、效果图、比较、指标。

只有在论证真正转折时才使用留白提问页、引语页或命题页。它们必须在后续 1–3 页得到回答。

故事板必须一次覆盖完整文稿。提交后停止，不得编写生成代码或制作任何页面，直到用户明确批准完整逐页故事板。

## 6. 先分配图片，再写文字

先放置最强的源视觉，再只写帮助阅读图片的文字。每张图片都要确定：

- 它是证据还是氛围；
- 使用全图、裁切、插图还是序列；
- 是否需要标题、批注或无需标注；
- 是否可作为定位图复用；
- 是否需要来源说明。

源图分辨率不足时，应作为小图使用或将其中的图解重新绘制为可编辑对象，不得把低清平面放大成模糊满版图。

## 7. 获批后按范围制作

生成前必须确保 review/project-state.json 中整体骨架和逐页故事板均已批准，本次章节或页码范围已由用户授权，并运行人工门禁检查器。

- 先确定页面尺寸、主题字体、颜色、标题坐标、页脚和基线网格，再做内容页。
- 建立 4–6 个类似母版的辅助函数或组件：基础页、章节页、图纸页、效果图页、深色概念页、比较页。
- 页标题、图名、指北针、图例和页码保持稳定位置。
- 保持原图宽高比。平面和证据图使用完整适配；只有氛围照片或效果图可以审慎裁切铺满。
- 所有承载结论的文字保持可编辑。面积表和进度表使用原生表格。
- 外部来源放在演讲者备注中；只有受众需要时才直接显示在页面上。
- 每个对话只处理获授权范围，并写入自己的章节目录。
- 多个对话可以并行处理不同章节，不要求按章节顺序推进。
- 每个范围完成后保存新的不可覆盖版本，输出可下载 PPTX 和页面预览。
- 修改已生成范围时另存新版本，不能覆盖旧文件。

## 8. 范围复核与最终合并

每个授权范围完成后立即复核：

1. 全尺寸逐页检查；
2. 用缩略图总览检查节奏和章节平衡；
3. 结合标题与正文核对结论是否成立；
4. 将图纸和图片裁切与原文件对照；
5. 顺序或素材变化后重新运行故事板检查器；
6. 保存可下载版本并更新版本清单；
7. 等待用户批准、修改或选择该范围版本；其他已授权范围可以继续并行工作。

只有用户明确选定需要合并的各范围版本后，才能合并完整文稿并执行最终质量门槛。
