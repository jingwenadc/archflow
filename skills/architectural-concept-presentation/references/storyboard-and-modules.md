# 叙事与逐页内容

## 设计提案的说服逻辑

让观众理解“这个设计为什么值得选择”：关心的问题 → 有辨识度的回应 → 看得见的体验/差异 → 有依据的价值 → 下一步决定。

顺序可以改变：强主视觉先建立兴趣，或先演示再解释。以下模块按需选择，不是固定目录：

| 项目 | 常用主线 | 值得创作的视觉 |
| --- | --- | --- |
| 空间、建筑、景观 | 使用问题 → 空间策略 → 路径 → 体验 | 关系示意、体量推导、路线叠图、场景效果 |
| 室内、展陈、活动 | 受众/主题 → 故事 → 体验序列 → 触点 | 参观分镜、展项演示、灯光/材质意向 |
| 品牌、视觉传达 | 定位 → 概念 → 视觉语言 → 应用 | 元素推导、版式试用、包装/招牌样机 |
| 实体产品 | 情境 → 回应 → 交互/结构 → 细节 | 操作分镜、构成爆炸图、产品场景 |
| 数字产品、服务 | 用户问题 → 核心任务 → 流程 → 界面 | 用户旅程、交互路径、界面演示 |
| 方案比选 | 标准 → 各方案特色 → 差异与取舍 | 同条件对照、取舍矩阵、重点放大 |

不需要图纸就不补图纸，没有数据就不编数据。拟议体验不等于已实现功能。

## 议程示例（纯文字）

项目：新产品体验提案。
受众与决定：让合作方认可体验方向，选择进入原型验证的路径。
主张：用连贯流程让用户理解并尝试核心功能。
建议章节：机会与目标 → 设计概念 → 核心体验 → 重点应用 → 下一步验证。
预计 10–14 页，随资料调整。
待确认：主打受众与目前可展示的原型范围。

此时只确认方向，不创作视觉或逐页页面。

## 逐页 Markdown 模板

### S05｜体验设计｜从理解到尝试

- 页面任务：让合作方看懂推荐的体验顺序。
- 实际标题：先看懂，再亲手试
- 上屏文案：用引导、体验与反馈串联一次完整尝试。
- 短标签：发现亮点 / 动手体验 / 看见反馈
- 主视觉计划：三幅同视角场景沿一条动线排列；中间体验场景较大；箭头只表达顺序。白底，青色仅标行动路径。
- 制作方法：基于用户原型生成演示图；标题、箭头和标签用原生对象后叠。只有流程资料时做矢量分镜，避免捏造产品形态。
- 依据：S02 体验目标；A03 用户原型。流程属于设计建议，无实测转化率。
- 待确认：反馈触点实际可用的功能。
- 希望观众记住：体验不是孤立功能，而是连贯过程。

这是内容与视觉意图的文字合同，不是最终画面；不能只写“介绍优势”“放一张好看的图”。

## 可选 JSON 字段

字段键用于脚本接口，内容使用中文：
- id / chapter / title / purpose / takeaway：稳定页号、章节、实际标题、页面任务、核心信息。
- copy：实际上屏短文案，可为空（纯主视觉页）。
- archetype：页面原型，可自定义为 custom 并在 visual_plan 描述构图。
- visual_plan：画什么、主要关系、如何制作。
- fact_status：fact / proposal / assumption / mixed；混合页在 evidence 逐项区分。
- evidence：来源或提案依据数组；事实/混合页不可为空。纯提案可说明逻辑，不伪造来源。
- assets：已有素材 ID；可为空，但视觉计划要说明如何创作。
- density：pause / explain / inspect；notes、reuse_reason 可补充限制与复用理由。

结构检查不能判断来源真假或美感，需要实际审阅。

## 文案编辑

空泛：“以人为本，打造高品质、全方位、智能化体验。”
有设计动作：“入口即体验起点”；辅以引导路径与触点图。没有相应设计时不用此标题。

冗长：“通过对不同功能的重新分配，实现使用者在不同区域之间更加清晰便捷的移动。”
精简：“一条路径串起三个功能区”；图中让三段关系可见，没有资料时不生造这个数字。

有冲击力不等于夸张承诺。可以突出特色、表达设计意图，不能把未实测的“更高效”写成“效率提升 40%”。
