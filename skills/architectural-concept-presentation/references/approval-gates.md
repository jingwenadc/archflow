# 人工审批门禁

生成演示文稿会消耗大量时间和计算资源。为避免方向偏离、内容返工和无效生成，本技能必须严格按照以下状态推进。前一阶段没有得到用户明确批准时，下一阶段保持锁定。

## 阶段 1：整体骨架

分析用户提供的任务书、图纸、效果图和参考资料，提交纯文字整体骨架，至少包含：

- 文稿目标和受众；
- 建议总页数与交付模式；
- 一级章节及排列顺序；
- 每章首先解释什么、最终证明什么；
- 各章节预计页数；
- 已有资料与缺失资料；
- 需要确认的关键假设。

此阶段只能输出 Markdown 或普通文字。禁止创建 PPTX、PDF、演示文稿代码、正式页面、页面预览、正式配图或批量生成图片。

提交后必须停止，等待用户明确批准整体骨架。

## 阶段 2：完整逐页故事板

整体骨架批准后，为全稿编写逐页 Markdown 故事板。不能只提交前几页后就开始制作。

每页必须包含：

- 页码和所属章节；
- 页面标题；
- 页面目的；
- 核心结论；
- 主要文字内容；
- 所需图纸、效果图、照片或数据；
- 页面原型；
- 缺失资料或待确认事项；
- 事实、设计提案、工作假设或占位内容的状态。

此阶段仍然禁止生成 PPTX、PDF、页面代码、正式页面预览或正式配图。

完整故事板提交后必须停止，等待用户明确批准逐页故事板。

## 阶段 3：按范围制作

只有完整逐页故事板批准后，才能制作幻灯片。制作采用范围授权，不采用固定章节顺序。

用户可以授权一个完整章节、一组不连续页面、某几页的重新设计，或只处理某一类页面。用户也可以打开多个对话，让不同 AI 分别处理不同范围。

每个对话开始生成前，必须声明本次范围、页码、预期输出和保存目录。用户明确授权后，该对话只能在所述范围内工作。

生成任何章节前，更新 review/project-state.json，并执行：

    python scripts/check_project_gate.py review/project-state.json --action generate-section --section <章节编号>

门禁不通过时不得继续。

每个范围完成后必须：

1. 保存新的、不可覆盖的 PPTX 版本；
2. 渲染该版本中的全部已完成页面；
3. 提供可下载的 PPTX；
4. 提供该章页面预览或 PDF；
5. 简要列出与已批准故事板之间的差异；
6. 更新版本清单与项目状态；
7. 等待用户批准、修改或选择该版本。

不同对话可以同时处理不同范围，不要求第 1 章批准后才能开始第 2 章。对已生成范围的修改必须形成新版本，不能覆盖旧文件。

## 阶段 4：完整合并版

用户明确选定所有需要纳入终稿的范围版本后，才能生成完整合并版。生成前执行：

    python scripts/check_project_gate.py review/project-state.json --action finalize

最终版必须只整合用户选定的版本，完成逐页渲染检查，并保存为新的最终版本，不覆盖任何历史文件。

## 什么才算批准

可接受的批准包括：

- “批准整体骨架”；
- “整体结构确认，可以进入逐页故事板”；
- “批准逐页故事板”；
- “制作第 2 章”或“修改第 12–16 页”；
- “第 2 章采用 v02 进入整合版”；
- 语义同等明确、能够对应具体阶段或章节的表达。

以下内容不算批准：

- 沉默或没有回复；
- “继续”“好的”“看看吧”“先做着”；
- 继续上传资料；
- 对个别页面提出修改；
- 只批准部分内容，却没有说明能否进入下一阶段。

无法确定时，按未批准处理并停止。

## 审批失效

如果用户修改已批准的章节结构、设计命题、关键项目条件、方案版本或页面顺序，受影响的故事板和章节批准自动失效。

必须先更新对应 Markdown，标出变化页，重新取得批准，再生成新版本。不得沿用已经失效的批准。

## 版本与下载

所有可供审阅的文件必须保存在项目交付目录，不能只存在于临时目录。建议结构：

    ArchFlow/项目名称/方案工作区/
    ├── 00_项目总控/
    ├── 01_整体框架/
    ├── 02_逐页故事板/
    ├── 03_章节设计/
    ├── 04_整合版本/
    ├── 05_终稿交付/
    └── 99_历史版本/

项目状态、审批记录、素材索引和版本清单保存在 00_项目总控。每个对话只能写入 03_章节设计 中自己获授权的子目录。

每个版本必须提供可点击下载链接。版本清单至少记录版本号、生成时间、包含章节、主要修改、批准状态和对应文件。

## 停止条件

出现以下任一情况时必须停止：

- 正在等待用户批准；
- 必要资料缺失会影响真实性；
- 用户修改导致已有批准失效；
- 门禁检查器未通过；
- 生成范围或当前有效方案不明确；
- 当前工作超出用户授权范围；
- 用户尚未选定用于最终整合的版本。

不得为了维持任务运行而自行补充重大事实、猜测用户选择、扩大工作范围或在后台预制未授权页面。
