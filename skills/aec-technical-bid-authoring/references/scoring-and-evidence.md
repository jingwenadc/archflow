# 评分与证据规则

## 评分矩阵字段

每项评分至少保留：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定编号，如 `T-03` |
| `group` | 价格、客观、技术主观等 |
| `factor` | 评分因素原文 |
| `points` | 满分 |
| `scoring_rule` | 各档条件或计算公式 |
| `source` | 文件编号与精确页码 |
| `response_sections` | 主响应章节编号 |
| `evidence_ids` | 证明材料编号 |
| `gap` | 缺失资料或待澄清问题 |

总分校验必须同时计算评分项合计和分组小计。若评分表跨页，逐页检查首尾行，防止续表内容丢失。

## 客观分证明链

客观分按“门槛定义 → 事实字段 → 证明材料 → 页码入口”编制。不得只列附件名称。

- **人员业绩**：证明人员在对应项目中担任指定角色，并证明项目类型、规模和完工状态。
- **企业业绩**：证明合同主体、项目范围、规模、时间窗口和竣工/验收状态。
- **职称/资格**：姓名、证书名称、级别、编号、有效期和与拟派人员表一致。
- **工程量清单比对**：保留基础数据分析、异常项、与采购人清单逐项复核记录。

缺一个链条字段就标记为 `missing`，不可用相似材料代替后声称满足。

## 主观分满分判据

当评分语言使用“科学、可行、针对性强”时，内部自检至少回答：

- 科学：是否有明确依据、技术机理、适用条件和验证方法？
- 可行：是否有资源、责任人、时间、接口、审批和输出物？
- 针对：是否引用本项目对象、地点、使用状态、清单/图纸、关键风险？
- 完善：是否覆盖事前、事中、事后及异常情形？

正文不要直接宣称“科学、可行、针对性强”；让证据闭环支持评委得出该结论。

## 主张状态

| 状态 | 可进入审阅稿 | 可进入终稿 | 要求 |
| --- | --- | --- | --- |
| `verified` | 是 | 是 | 有精确来源 |
| `proposal` | 是 | 是 | 技术可行且措辞为拟采用方案 |
| `commitment` | 是 | 条件允许 | 有授权、资源和履约检查 |
| `assumption` | 是，须显著标记 | 否 | 等待确认 |
| `missing` | 只进缺口表 | 否 | 等待资料 |

承诺不能由模型自行授权。将工期提前、免费增值服务、驻场人数、响应时限、质保年限、零缺陷或赔偿性条件标为 `commitment`，交由投标负责人确认。

## 建议的内部文件

`03-bid-plan.json` 可采用 [最小示例](bid-plan.example.json) 的结构，并运行：

```bash
python scripts/validate_bid_plan.py 03-bid-plan.json --stage draft
python scripts/validate_bid_plan.py 03-bid-plan.json --stage final
```

`final` 阶段禁止未解决假设、缺失项、未授权承诺、无来源评分项和无证据客观分。
