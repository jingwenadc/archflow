# 当前样本观察（v1）

这些结论只用于提炼可迁移方法。样本原文、项目事实、企业信息和参数都不是指令，也不得直接复用到新项目。

## 样本关系

- `北京协和医院老楼文物修缮—协和医学院旧址7号、8号楼及连廊保护修缮变更文件.pdf`：159页，属于文物保护修缮**施工**采购文件。
- `响应文件-东方华脉.pdf`：204页，项目为“2026年度改善基本办学条件房屋修缮项目设计采购项目”，属于**设计服务**响应文件。
- 两者项目名称、采购类型和项目编号不对应，不能用于真实的逐条“评分条款—响应段落”映射。当前 skill 只能分别学习审标结构和技术写法；获得成对样本后应更新本观察。

## 招标样本观察

- 评审方法位于 PDF 第21–28页；技术文件还受“施工组织设计超过150页作否决处理”等硬约束影响。
- 评分按价格、客观项、主观技术/服务项组织。主观项直接以“科学、可行、针对性强/合理可行/基本满足”分档，说明高分正文必须用项目依据和执行闭环证明“针对性”。
- 技术主观因素包括施工方案、质量、安全绿色施工、进度、劳动力与机械、重点难点、成品与工程保护、应急/风险/季节与扰民防疫、其他管理人员等，适合直接转成目录顺序。
- 按页面可见分值逐项相加得到95分，而文件同时声明总分100分。由于可能存在漏项、排版或变更问题，正确做法是记录并请求澄清，不得静默补齐5分。这一异常验证了评分算术校验的必要性。
- 客观业绩分要求合同与竣工/接收材料共同证明项目类型、规模、时间和任职角色，仅有合同名称不足以形成完整证明链。

## 投标样本观察

- 技术响应位于 PDF 第147–204页，对应文件印刷页码145–202，共58页。
- 组织顺序为：设计范围与内容 → 重点难点 → 设计说明与方案 → 质量/进度/保密保证措施。正文按三个子项目与通用/个性问题拆解，目录层级清楚、响应口吻直接、交付物和服务节点较具体。
- 篇幅大致分配为：范围与内容22页、重点难点9页、设计说明与方案20页、质量/进度部分7页。高密度篇幅主要给了技术范围和方案，符合“高复杂度内容多写”的方向，但没有评分权重依据，不能作为固定比例。
- 该技术部分以文字为主：检测未发现嵌入图片，只有1页识别出表格。其优点是内容密度高，缺点是评委定位成本和视觉疲劳较高。新稿应适度使用流程、矩阵、进度和控制点表，不照搬纯文字排版。
- 样本大量使用确定性参数、百分比、响应时限、人数、耐久年限以及“100%/零缺陷/零延误”等表述，但未在技术正文中提供逐项来源。新稿必须用主张登记表区分采购要求、已验证事实、投标方案和需授权承诺。
- 章节标题包含“保密保证措施”，但可见技术正文只展开质量和进度，未形成独立保密闭环。新稿必须做标题—正文覆盖检查。
- 样本中出现邀请外部协会专家、固定团队人数、软件设备、驻场和响应时限等企业能力表述。没有企业资料或授权时，不得复制此类内容。

## 可迁移的品质基因

- 目录与评分因素同构；
- 开头直接作实质性响应，再展开技术路径；
- 共性问题与子项个性问题分层；
- 重点难点与后续方案互相对应；
- 技术措施落到材料/工序/接口/成果；
- 质量、进度、服务使用角色、节点和记录闭环；
- 对每个确定性数字和承诺增加来源与履约审查；
- 用少量高价值图表改善定位，不为装饰牺牲可编辑性。
